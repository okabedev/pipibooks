# 피피북스 마일스톤

마일스톤 하나를 시작하고, 중간에 이어 가고, 끝내는 절차다. 마일스톤 목록과 파일 형식은 `docs/roadmap/README.md`에 있다.

## 어느 동작인지 고르기

`docs/roadmap/README.md`의 표를 본다.

위에서부터 처음 맞는 것을 고른다.

1. 사용자가 마무리를 요청했거나, `진행` 마일스톤 계획의 모든 Task가 끝났다 → **종료**
2. 상태가 `진행`인 마일스톤이 있다 → **재개**
3. 없다 → 첫 번째 `대기` 마일스톤을 **시작**

## 모든 동작에 공통

- 승인이 필요한 결정(`docs/conventions/decision-making.md`)이 생기면 멈추고 묻는다. 승인을 받으면 `docs/decisions/`에 기록한다.
- push, PR 병합, 태그 push는 하기 전에 사용자에게 확인한다.
- 세션을 끝내기 전에 마일스톤 파일의 인계 메모를 갱신하고 커밋한다.

## 시작

- [ ] 마일스톤 파일을 읽는다. 앞 마일스톤의 인계 메모에서 "주의할 점"과 "남은 작업"도 확인한다.
- [ ] `develop`을 최신으로 받고 `feature/m<N>-<이름>` 브랜치를 만든다. 이름은 마일스톤 파일의 "브랜치" 항목을 쓴다.
- [ ] 마일스톤 파일과 `docs/roadmap/README.md` 표의 상태를 `진행`으로 바꾼다.
- [ ] 태그 항목이 "미정"이면 사용자에게 묻고 결정을 기록한다.
- [ ] `superpowers:writing-plans`로 계획을 `docs/superpowers/plans/YYYY-MM-DD-m<N>-<이름>.md`에 작성한다. 마일스톤 파일의 범위와 완료 기준, `docs/`의 관련 문서를 근거로 삼는다.
- [ ] 계획에서 완료 기준이 구체화되면 마일스톤 파일의 완료 기준도 고친다.
- [ ] 마일스톤 파일의 "계획" 항목에 링크를 걸고 함께 커밋한다.

## 재개

- [ ] `진행` 마일스톤 파일의 인계 메모(진행 상황, 남은 작업, 결정, 주의할 점)를 읽는다.
- [ ] 그 마일스톤의 feature 브랜치로 전환한다. 커밋되지 않은 변경이 있으면 먼저 사용자에게 알린다.
- [ ] 계획 파일에서 체크되지 않은 첫 단계를 찾는다. `git log`로 이미 커밋된 작업인지 확인한다.
- [ ] 그 단계부터 이어 간다.

## 종료

- [ ] 완료 기준을 하나씩 실제로 검증한다(`superpowers:verification-before-completion`). 명령 출력이나 실행 결과로 확인한 것만 체크한다. 병합과 태그는 완료 기준에 넣지 않는다. 이 절차의 뒷단계가 맡는다.
- [ ] 통과하지 못한 기준이 있으면 종료하지 않는다. 남은 작업으로 인계 메모에 적고 사용자에게 알린다.
- [ ] 인계 메모를 갱신한다. "주의할 점"에는 다음 마일스톤이 알아야 할 것을 적는다.
- [ ] 마일스톤 파일과 `docs/roadmap/README.md` 표의 상태를 `완료`로 바꾸고 커밋한다.
- [ ] `docs/conventions/git.md`대로 feature 브랜치를 `develop`에 PR로 병합한다.
- [ ] 마일스톤 파일의 태그 항목에 따라 릴리스한다. "생략"이면 건너뛴다. 절차는 `docs/conventions/git.md`의 릴리스 절차다.
- [ ] 병합과 태그가 원격에 반영됐는지 확인한다(`git fetch` 후 `git log origin/develop`, `git ls-remote --tags origin`).
- [ ] 다음 `대기` 마일스톤의 이름과 범위를 사용자에게 안내하고, 새 세션에서 이 스킬로 시작하라고 알린다.
