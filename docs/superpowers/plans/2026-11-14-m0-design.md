# M0 설계 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계서를 `docs/` 아래 주제별 문서로 옮기고, CLAUDE.md·로드맵·`pipibooks-milestone` 스킬을 만들어 다음 세션이 문서만 보고 M1을 시작할 수 있게 한다.

**Architecture:** 코드 없이 문서만 만든다. 설계서 각 절을 한 주제당 한 파일로 옮기고, `docs/README.md`가 목차, `CLAUDE.md`가 규칙 요약과 안내를 맡는다. 마일스톤 진행은 `docs/roadmap/`의 파일과 `.claude/skills/pipibooks-milestone/SKILL.md`로 이어 간다.

**Tech Stack:** Markdown, Git(Git Flow), GitHub CLI(`gh`)

**Spec:** `docs/superpowers/specs/2026-11-14-pipibooks-design.md`

## Global Constraints

- 주석, 문서, 커밋 요약은 한국어로 쓴다. 식별자와 파일 이름은 영어로 쓴다.
- `CLAUDE.md`는 200줄 이하로 쓰고, 규칙 요약과 문서 안내만 담는다.
- 나머지 문서는 한 파일에 한 주제만 담고 300줄 정도까지 쓴다.
- 의미를 흐리는 축약은 하지 않는다. 현재 승인된 축약어는 NLK 하나다(ISBN, KDC, JWT, API 같은 고유 명사는 예외).
- 커밋은 Conventional Commits 형식이고, type과 scope 모두 `docs`다. 예: `docs(docs): 제품 문서 추가`.
- 작업 브랜치는 `develop`에서 만든 `feature/m0-design`이다. PR로 `develop`에 병합한다.
- M0는 릴리스와 태그를 생략하고 `develop` 병합까지만 한다. 첫 태그는 M1의 `v0.1.0`이다. M0 결과물은 문서뿐이라 출시할 소프트웨어가 없기 때문이다 (사용자 승인, 2026-11-14).
- 원본 설계서는 기록으로 보존한다. 상태를 "승인"으로 고치고 이후 기준 문서는 `docs/`의 주제별 문서라는 안내를 붙인다. 그 뒤로는 고치지 않는다 (사용자 승인, 2026-11-14).
- API 키, 토큰 등 비밀 값은 문서와 커밋에 남기지 않는다.
- 문서 내용은 설계서를 옮기는 것이다. 설계서에 없는 정책을 새로 만들지 않는다. 옮기다가 애매한 부분이 나오면 멈추고 사용자에게 묻는다.

2. **깨진 상대 링크:** 문서끼리 링크가 많다. Task 6의 링크 검사 명령으로 확인한다.
3. **줄 수 제한 초과:** CLAUDE.md 200줄, 나머지 문서 300줄 정도. Task 6의 `wc -l` 검사로 확인한다.
4. **새 세션이 시작 지점을 못 찾는 경우:** CLAUDE.md만 읽은 세션이 로드맵 → 현재 마일스톤 → 인계 메모 순서로 M1을 시작할 수 있어야 한다. Task 5의 확인 단계에서 점검한다.
5. **비밀 값 노출:** 키 이름은 적어도 되지만 값은 안 된다. Task 6의 grep 검사로 확인한다.
