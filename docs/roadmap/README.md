# 로드맵

마일스톤 순서와 세션을 이어 가는 방법이다. 각 마일스톤의 범위, 완료 기준, 상태, 인계 메모는 마일스톤 파일에 있다.

## 마일스톤

| 마일스톤 | 범위 | 상태 |
|---|---|---|
| [M0 설계](m0-design.md) | `docs/` 구성, CLAUDE.md, 스킬, Git 레포와 브랜치 | 완료 |
| [M1 기반](m1-foundation.md) | Gradle 멀티 모듈 뼈대, 웹 뼈대, 로컬 Compose(PostgreSQL), Flyway, 공통 오류 응답, 헬스 체크 | 대기 |
| [M2 인증](m2-authentication.md) | 카카오 로그인, JWT, 회원·닉네임, 탈퇴 | 대기 |
| [M3 도서](m3-books.md) | `services/client`(nlk, kakao), 검색, 도서 상세, 도서 저장·병합, KDC 분류 | 대기 |

상태는 `대기` / `진행` / `완료` 중 하나다. 마일스톤 파일의 상태를 바꾸면 이 표도 함께 고친다.

## 마일스톤 파일

마일스톤마다 하나씩 두며 다음 형식을 따른다.

```markdown
# M<N> <이름>

- 상태: 대기 | 진행 | 완료
- 브랜치: `feature/m<N>-<이름>`
- 계획: (작성 후 링크)
- 태그: `v0.N.0`

## 범위
## 완료 기준
## 인계 메모
### 진행 상황
### 남은 작업
### 진행 중에 내린 결정
### 주의할 점
```

인계 메모에는 진행 상황, 남은 작업, 진행 중에 내린 결정, 주의할 점을 적는다. 세션을 끝내기 전에 항상 갱신한다.

## 세션 흐름

1. `pipibooks-milestone` 스킬로 마일스톤을 시작한다.
2. `superpowers:writing-plans`로 구현 계획을 작성한다. 계획은 `docs/superpowers/plans/`에 저장한다.
3. 계획을 실행한다.
4. `pipibooks-milestone` 스킬로 마일스톤을 종료한다.

구현 계획은 각 마일스톤을 시작할 때 쓴다. 미리 써 두지 않는다.

## 세션이 바뀔 때

새 세션은 다음 순서로 읽고 시작한다.

1. 이 문서에서 상태가 `진행`인 마일스톤을 찾는다. 없으면 첫 번째 `대기` 마일스톤이다.
2. 그 마일스톤 파일을 읽는다.
3. 마일스톤 파일의 인계 메모를 읽는다.

## 승인이 필요한 결정

진행 중에 생기면 작업을 멈추고 사용자에게 묻는다. 임시로 정하고 넘어가지 않는다. 승인을 받으면 [결정 기록](../decisions/README.md)에 남긴다. 범위는 [결정 방식](../conventions/decision-making.md)에 있다.

## 미리 준비된 것

- 카카오 개발자 앱
- 국립중앙도서관 인증키
- Cloudflare의 `pipibooks.com` 도메인
- GitHub 레포 `pipibooks`와 `main`·`develop` 브랜치

키는 `.env`로만 다루고 문서나 커밋에 남기지 않는다.
