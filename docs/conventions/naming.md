# 이름 짓기와 언어

이 규칙은 스킬로 만들지 않고 이 문서와 CLAUDE.md로만 안내한다([Git 규칙](git.md) 참고).

## 가독성 우선

- 가독성을 최우선한다. 의미를 흐리는 축약은 하지 않는다.
- 예: `rvw`, `cnt`, `usr` 대신 `review`, `count`, `user`.

## 축약이 허용되는 경우

- 고유 명사로 쓰이는 축약: ISBN, KDC, JWT, API 등
- 긴 명칭: National Library of Korea → NLK
- 3 단어 이상으로 이루어진 명칭

이 예외에 해당하는 축약어는 **사용자의 승인을 받은 뒤에만** 쓴다. 승인된 축약어는 [축약어 목록](../decisions/abbreviations.md)에 기록한다. 현재 승인된 것은 API, ISBN, JWT, KDC, NLK다.

새 축약어가 필요하면 작업을 멈추고 사용자에게 묻는다. 승인을 받으면 목록에 행을 더한 뒤에 쓴다.

## 언어

- 식별자(클래스, 함수, 변수, 파일 이름)는 영어로 쓴다.
- 주석, 문서, 커밋 요약은 한국어로 쓴다.

## 용어

도메인 용어는 식별자, 파일 이름, 브랜치 이름에서 아래 영어 이름으로 통일한다. 비슷한 다른 단어는 쓰지 않는다.

| 한국어 | 영어 | 쓰지 않는 단어 |
|---|---|---|
| 나의 책장 | `bookcase` | `bookshelf` |

새 용어를 정하거나 바꾸는 것은 사용자의 승인을 받은 뒤에 이 표에 더한다.
