# 결정 방식

무엇을 구현자가 정하고, 무엇을 사용자에게 물어야 하는지 정리한다.

## 승인이 필요한 결정

- 정책이 바뀌는 결정
- 새로 쓰려는 축약어([이름 짓기와 언어](naming.md))
- 문서에 정해지지 않았고 구현자에게 맡긴 범위에도 들지 않는 결정

진행 중에 이런 결정이 생기면 작업을 멈추고 사용자에게 묻는다. 임시로 정하고 넘어가지 않는다. 승인을 받으면 [결정 기록](../decisions/README.md)에 남긴다.

## 구현자에게 맡기는 것

- ERD와 테이블 세부 설계, API 경로와 요청·응답 형식
- 화면의 세부 디자인
- 패키지 내부의 클래스 구성
- 타임아웃, 토큰 수명, 스케줄 주기의 구체적인 값

다만 이 범위 안이라도 정책이 바뀌는 결정이나 새로 쓰려는 축약어는 반드시 사용자의 승인을 받는다.
