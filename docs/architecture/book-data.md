# 도서 데이터

도서를 어떻게 식별하고, 언제 저장하고, 외부 API에서 어떻게 검색하고 병합하는지 정리한다. 화면에 보여 주는 정책은 [도서 정보](../product/books.md)에 있다.

## 식별

도서는 ISBN-13을 기준으로 식별한다.

## 저장 시점

- 사용자가 도서 상세를 처음 조회하거나, 평가하거나, 위시에 담을 때 저장한다.
- 워커가 신간을 수집할 때도 저장한다([워커](worker.md)).

## 검색

- 국립중앙도서관 ISBN 서지 API를 먼저 쓴다.
- 결과가 0건이거나 호출이 실패할 때만 카카오 도서 검색 API를 쓴다.
- 결과는 ISBN-13 기준으로 중복을 없앤다. 페이지 나누기는 실제로 응답한 API의 방식을 따른다.
- 외부 API 호출에는 짧은 타임아웃을 둔다.
- 두 API가 모두 실패하면 저장된 도서를 제목으로 간단히 찾는다(`LIKE`). 한국어 전문 검색은 넣지 않는다.

## 외부 API를 어디서 호출하는가

외부 API 클라이언트(`services/client`)는 라이브러리다. 애플리케이션은 작업의 성격에 따라 나눈다.

- 사용자 요청에 바로 응답해야 하는 작업(검색, 저장되지 않은 책의 상세 조회)은 API 서버가 직접 처리한다.
- 오래 걸리거나 주기적으로 도는 작업은 워커가 처리한다.

검토했다가 버린 안은 [0002. 외부 API 호출 위치](../decisions/0002-external-api-call-location.md)에 있다.

## 필드 병합

- 서지 정보(페이지 수 포함)는 국립중앙도서관 데이터를 기본으로 쓴다.
- 표지 이미지와 소개글이 비어 있으면 카카오 데이터로 채운다.
- 카카오 API는 페이지 수를 주지 않는다.

## API 키

- 국립중앙도서관 인증키, 카카오 REST API 키를 쓴다.
- 카카오 키는 로그인과 같은 앱의 키를 쓴다.
- 키 값은 `.env`로만 다룬다([인프라](infrastructure.md#비밀-값)).
