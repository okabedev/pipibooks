# 0004. 인증 방식

- 상태: 승인 · 2026-11-05

## 맥락
1인 운영이므로 비밀번호와 메일 인프라 부담을 피하고 싶다. 웹과 앱이 같은 인증을 써야 한다. iOS에서 서드파티 로그인을 제공하면 Apple 로그인도 사실상 필수다.

## 결정
- 카카오와 구글 소셜 로그인만 제공한다. 앱 출시 때 Apple을 추가한다.
- 자체 JWT를 발급한다: Access 15분, Refresh 30일(불투명 토큰, DB에는 해시 저장, 재발급 시 교체, 재사용을 감지하면 폐기)
- 웹은 Refresh 토큰을 `HttpOnly` 쿠키로, 앱은 SecureStore로 보관한다.
- 피드는 로그인 없이 볼 수 있다. 서재, 기록, 개인화에는 로그인이 필요하다.

## 결과
- 장점: 비밀번호 유출 위험이 없고 운영이 가볍다.
- 단점: 소셜 계정이 없는 사용자는 가입할 수 없다.

## 검토한 대안
- 이메일/비밀번호, 매직링크: 메일 발송과 재설정 흐름의 운영 부담이 크다.
