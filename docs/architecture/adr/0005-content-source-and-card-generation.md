# 0005. 콘텐츠 원천과 카드 생성

- 상태: 승인 · 2026-11-05 · 발행 방식은 0011로 대체됨

## 맥락
혼자서 카드 콘텐츠의 양을 확보해야 한다. 외부 도서 API는 일관성을 위해 하나로 유지한다.

## 결정
- 외부 도서 API는 **국립중앙도서관 ISBN 서지정보 API 하나**만 쓴다. 사서추천 API를 포함한 다른 API는 쓰지 않는다. 호출은 catalog-worker만 한다.
- 수집 대상을 고르는 경로: 신간(출간일 범위 조회), 운영자 시드, 사용자의 서재 추가
- `CardDraftGenerator` 인터페이스를 두고, 지금은 규칙 기반 구현을 쓴다. LLM 구현은 나중에 교체해 붙인다.
- 관리자가 초안을 검수·편집해 발행한다. 사용자 생성 카드(UGC)는 나중에 다룬다.

## 결과
- 장점: 비용이 0이고 저작권·환각 위험이 적다. 연동 지점이 하나라 단순하다.
- 단점: 자동 카드 문구가 밋밋할 수 있어 큐레이션으로 보강해야 한다. API 기능(검색, 기간 조회)은 구현 전에 확인이 필요하다.

## 검토한 대안
- 사서추천 API 병행: 연동 대상이 늘어나 제외했다.
- 클라우드·로컬 LLM: 인터페이스만 미리 두고 나중에 도입한다.
