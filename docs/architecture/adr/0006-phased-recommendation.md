# 0006. 단계적 추천 전략

- 상태: 승인 · 2026-11-05

## 맥락
초기에는 협업 필터링을 할 만큼 데이터가 없다. 하지만 행동 로그는 나중에 소급해서 모을 수 없다.

## 결정
- 1단계: 규칙 기반 개인화(관심 KDC, 서재 KDC 유사도, 인기도, 신선도, 무작위 항). `FeedRanker` 인터페이스 뒤에 둔다.
- MVP부터 행동 이벤트(노출, 슬라이드 조회, 체류, 스킵, 공유, 서재 추가, 상태 변경)를 `events` 스키마에 적재한다.
- 2단계: 데이터가 일정 수준을 넘으면 추천 워커(협업 필터링이나 임베딩)를 추가하고 `FeedRanker` 구현을 교체한다. 착수 기준은 서브프로젝트 2가 끝날 때 정한다.

## 결과
- 장점: 초기 복잡도는 낮게 유지하면서 확장 경로를 열어 둔다.
- 단점: 이벤트 저장 용량이 늘어난다. 월별 파티션과 보관 정책으로 관리한다.
